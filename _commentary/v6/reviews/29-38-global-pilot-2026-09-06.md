## Findings from the completed run

### 1. A mechanically valid facet is semantically wrong

`global:0d0a8651cf8736a990ff` interprets the dwellings as an invitation to
investigation. Its activation of `root_000726/B009` selects `F001`, whose exact
statement concerns the point where the head rests on the neck. The activation
cites the dwelling noun `29:38:7:1` and provides no anatomical mechanism.

The same source branch offers `F002`, an associated use covering positions,
homes, and customary arrangements. That facet requires its own interpretive
assessment. Selecting the first/core facet supplied an exact registered string
without establishing that its meaning supports this finding.

The producing agent's generation script confirms the immediate cause:
`facet_for()` returns the first core facet unless explicitly overridden, then
falls back to the first facet. Its carrier helper also defaults missing focus
carriers to the dwelling morpheme `29:38:7:1`. These defaults were authored by
the pilot agent; they are not V6 helper functions. The workflow's validator
accepted the resulting registered identities without judging their semantic fit.

All 28 activations repeat the same generic activation sentence, and their
independent-trigger explanations are also identical. Several evidence facts
merely assert that an ayah supplies a trigger, without stating its relevant
wording or relation. The broader finding claims contain useful interpretations,
but these repeated fields do not substantiate the individual facet choices or
carry sufficient source detail into composition.

### 3. Delivery accounting overstates the evidence presented to the model

Several tool wrappers projected or filtered helper responses before returning
them to the model. For example, a connection-page wrapper kept connection rows
and removed context rows; connection batch 002 page 1 contained five such
context records. Some branch projections retained only `statements.statement`,
dropping source-image statements stored under `image_ar` and `image_en`.

The final catalog pass also projected branch records to glosses and facet IDs,
and projected connection records to ID, target, and forward note. This removed
facet wording and reciprocal evidence. A reciprocal seed such as `2:256` has a
null forward note but a substantive reciprocal nomination and supplied Arabic.

Detailed morphology can reasonably be reopened as needed. The problem here is
that semantic material was also omitted while helper delivery counters and the
final review narrative indicated full inspection. The frozen packet retains the
data; the trace shows incomplete presentation to the model.

## Overhead and next test

The trace records 108 orchestration tool calls and approximately 20m 37s elapsed.
Reported cumulative usage is 12,573,545 input tokens, including 12,119,808 cached
input tokens, and 47,936 output tokens, including 17,600 reasoning tokens. These
are totals across requests; repeated conversation context is counted repeatedly.
They are not the packet's token count or a price estimate. The observed lossy
reads also prevent treating this as the cost of the intended complete review.

Before a scale test, tighten the existing procedure:

1. Require a source-grounded batch checkpoint before progression to the next
   batch, and validate its pointers at completion. Keep summaries short and
   preserve unresolved leads without imposing a discovery quota.
2. Require semantic pages and catalogs to reach the model intact. Code can
   organize already-read material and copy exact identifiers; it should not
   silently select the evidence that counts as reviewed.
3. Require actual facet judgments and concrete source facts. Core status alone
   cannot justify a facet, and reusable boilerplate cannot supply an independent
   trigger or explain an activation. Context branches should retain their actual
   context carriers and return separately to the focus.

Repeat a fresh 29:38 global run after those changes, inspecting both its final
analysis and pre-compaction checkpoints. Then run the approximately 7.44 MB
22:5 global packet to assess scale. This pilot tested one medium-size global
discovery run; scope prose, consolidation, and large-packet performance remain
outside its observed results.
