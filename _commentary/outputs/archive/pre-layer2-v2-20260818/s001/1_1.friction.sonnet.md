# Friction — 1:1 (sonnet lane)

1. **word_analysis / QAC word-count mismatch, silently present in the bundle.** `word_analysis` counts five "critical words" (بِ, سْمِ, ٱللَّهِ, ٱلرَّحْمَٰنِ, ٱلرَّحِيمِ) while `qac_morphemes` counts four QAC words (بِسْمِ fused as one, then ٱللَّهِ, ٱلرَّحْمَٰنِ, ٱلرَّحِيمِ). Each `word_analysis` entry carries an `aligned_qac_word_ref` that is off by one from word 3 onward, and `coverage.word_analysis_qac_alignment` flags this explicitly (`consistent: false`, `dangling_refs: ["1:1:5"]`, "word-level joins between word_analysis topics and QAC morphology are UNRELIABLE here"). This is not ambiguous in outcome — the coverage block tells the writer to use `word_morpheme_spans` instead, which I did — but it is friction in the sense that the task prompt gives no explicit instruction for handling a documented upstream identity defect; I resolved it by trusting the bundle's own coverage note over the naive field name, per Principles §11's crosswalk requirement.

2. **The "before and after" instruction and the grounding rule for neighbouring-ayah words are in tension, and the tension is not resolved anywhere in the inlined governing documents.** The task instructs the writer to render what the hermetic focus trace's `context_deltas` show later ayahs (1:2–1:7) activating, and to render this "as reading experience." The grounding rule under "Keep the reader's feet on the ground" separately requires that when a later ayah's word is what makes a reading visible, that word receive "its own full span before leaning on it." But this bundle is hermetic to 1:1: it carries only root letters and branch IDs for words in 1:2–1:7 (inside `v12_focus_trace_hermetic.context_deltas[].activation_trace[].source_ref/root/branch_id`), never their QAC surface forms or morpheme data — there is nothing to build a `{ar:...,tr:...,gloss:...}` span from. I resolved this by following the precedent set inside `docs/CHANNELS.md`'s own worked example for 1:6–1:7, which cites forward material with bare backtick transliteration (`` `na'budu` ``, `` `En'amte` ``) rather than a full structured span. I applied the same convention: full spans only for this ayah's own five words; bare Turkish transliteration, no Arabic, for any word named in a forward reference (1:2, 1:3, 1:4, and 9:128). This is a judgment call, not a rule stated anywhere in the inlined documents, and a different reviewer could reasonably require the forward material to be dropped instead of lightly transliterated.

3. **9:128 is cited by a bundle topic but is not itself in the bundle.** `word_analysis` topic `1:1:5:shareable-form-contrast` states, as part of its own `reader_payoff`, that the {al-rahimi} form "can describe enacted compassion beyond the exclusive first mercy title, including the Prophet at 9:128." This is bundle-traceable as a claim (the topic itself asserts it, with `evidence_checked` including `critical:inter_ayah_reference`), but 9:128 has no word-level entry anywhere in this bundle — no Arabic surface, no root, no branch. Principles §1 gives almost this exact case as the standard for what counts as a violation ("If a reading needs 55:9, then 55:9 must be in the bundle"). I judged that citing 9:128 by ayah-number only, without any Arabic content, stays inside the bundle's own claim rather than importing outside knowledge — but this is a narrow reading of §1, and a stricter one would drop the reference entirely rather than cite a bare ayah number.

4. **Candidate-admission is a judgment call with no hard boundary.** This ayah's `word_analysis` carries 9 `must_integrate` topics and 15 `candidate` topics. The task says to admit a candidate "because it adds a distinct reader payoff," and warns "surprise alone does not justify inclusion," but gives no test for how many distinct payoffs is too many for a five-word ayah. I admitted all 15, on the reading that each one's stated `reader_payoff` was genuinely distinct from the others (verified word by word in the evidence surface) rather than a restatement — but a different writer applying the same instruction could reasonably cut several of the lighter apparatus candidates (`case-variant-apparatus`, `variant-and-pause-bridge`) as texture rather than payoff, producing a shorter commentary that would still pass the letter of the rule.

5. **`channel_generated_outputs` grants file access that this run did not use.** The manifest names 13 external quran-data network-v3 files (channel_candidates, families, path families) as readable "when channel-family or path detail is necessary." I did not read them. `channel_subchannels_anchored_here` (23 rows anchored at 1:1, already inlined) supplies the same root:branch/mNN-level material those files exist to generate, and the task confines ayah-level channel use to noticing a locally grounded resonance already supported by word evidence — never to naming, maturing, or asserting recurrence of a channel. Given that ceiling, the raw discovery files could only have supplied more candidates for material I am not permitted to render as a channel anyway. This is a defensible but unforced scope decision, not a rule the prompt states outright ("read them only when necessary" leaves "necessary" to the writer).

6. **Style note, not friction:** the negation-avoidance table in the task prompt bans `ötesinde`, `yerine`, `sadece … değil`, `-den ziyade`, `aşarak`. I found no place in this ayah's material where avoiding those forms cost a needed contrast — the "X — as Y" containment pattern (`{ar:...} olmakla birlikte, aynı zamanda ... olarak da işler`, `değişmez, ... somutlaştırır`) covered every case where a secondary reading needed to sit inside the primary one. Flagging only because the prompt asks profile-specific style audits to be labelled as such rather than as friction, and this is the one place I actively checked against the table.
